# room モード：仮想の部屋での日差しプレビュー

計算した太陽の位置・光の向きが、実際の空間の中でどう見えるかを確認するためのモード。
白いボックスの仮想の部屋（[sunabako](https://www.sunabako.jp/space/) のようなホワイトボックスの撮影スタジオが参考）に、環境光とスポットライトを置き、日差しの計算結果をそのまま反映する。展示（kiosk）には出ない、検証・確認用の画面。

対象コード：`src/room/scene.ts`（3D シーン）、`src/ui/room.ts`（時刻操作・状態表示）、`src/main.ts`（配線）。

---

## 1. 座標系の再利用

`src/solar.ts` の `lightOnScreen()` が返す `light.x, light.y, light.z` は、もともと画面（スクリーン）に対して「光が進む向き」を、鑑賞者から見た右・上・スクリーンの奥、の 3 軸で表したベクトルである（`docs/verification.md` 5 章）。

これは実は、部屋を「鑑賞者側が開いた箱」と見立てたときの部屋のローカル座標系と完全に一致する：

| 軸 | screen 座標での意味 | room モードでの部屋の軸 |
|---|---|---|
| x | 右（`rightAzimuth` 方向） | 窓のある側の壁（`window.side` で決まる） |
| y | 上 | 天井の方向 |
| z | スクリーンの奥（`facingAzimuth` 方向） | 奥の壁（スクリーン側） |

そのため room モードでは、`light` ベクトルを変換せずにそのまま「太陽の方向」として使っている（実際に太陽がある向きは、光が進む向きの逆＝`(-x, -y, -z)`）。**窓の位置（`window.side`）や緯度経度が変わっても、この関係は変わらない**（`resolveSite()` が方位の変換を先に済ませているため）。room モード側のコードを変更する必要はなく、`config/site.json` を差し替えるだけでよい。

## 2. 部屋の構成

- 床・天井・壁 4 面（白いマット素材）でできた直方体。寸法は `config/site.json` の `room.widthM` / `depthM` / `heightM`
- 窓のある壁だけ、窓の実寸（`window.widthM` / `heightM` / `sillHeightM`）ぶんの開口を、4 枚の壁パネル（窓の上・下・手前・奥）で囲んで作る
- 奥の壁（+z 側）がスクリーン側に相当する。窓は `window.side` に応じて左右どちらかの壁に開く
- カメラは部屋の外（鑑賞者が普段いる側）から室内を見下ろす位置に置き、`OrbitControls` で自由に視点を動かせる

## 3. 光の設定

| 要素 | 実装 |
|---|---|
| 環境光 | `THREE.HemisphereLight`。空の色（`sky.top` / `sky.bottom`、太陽高度から決めた色）を反映し、太陽高度が高いほど強くする。夜でも部屋の形が見える最低限の強さは保つ |
| 太陽 | `THREE.SpotLight`。影を落とす（`castShadow`）ので、窓のない壁側は光が入らず、窓の開口の形に光が切り取られる |
| 太陽の向き | `light.{x,y,z}` の逆向き（太陽がある方向）に、部屋よりじゅうぶん遠い位置へスポットライトを置く。`decay=0`（距離による減衰なし）：太陽は部屋に対して十分遠く、実際の日差しも距離では弱まらないため |
| 太陽の強さ | `lit`（0〜1、窓から光が入る度合い）に比例。窓から入らない時間帯（`entersWindow=false`）は 0 |
| 太陽の色 | `lightColor`（太陽高度から決めた色温度の RGB）をそのまま使う |
| 窓の外の背景 | 空の色（`sky.top`）。窓を真っ黒の穴に見せず、外が明るい・暗いを表す |

## 4. 物理との対応

| 現象 | 対応 | 補足 |
|---|---|---|
| 太陽の向き・窓から入るか | ◯ | `src/solar.ts` の計算をそのまま使う（検証済み。docs/verification.md） |
| 光の強さ（`lit`）との連動 | ◯ 考え方 / △ 値 | 「窓から入る度合いが強いほど明るい」という関係は反映しているが、スポットライトの強さの目盛り自体は演出上の値（`SUN_INTENSITY` 定数） |
| 太陽光を点光源（スポットライト）で表現 | △ | 実際の太陽光はほぼ平行光線（`DirectionalLight` 相当）だが、窓の開口による影の切り取りを分かりやすくするため `SpotLight` を使っている。`decay=0` にして距離による減衰だけは物理から外している |
| 環境光の色・強さ | △ | 空の色の目安の表（`palette.ts`）から。実際の相互反射（グローバルイルミネーション）の計算はしていない |
| 影の柔らかさ | △ | `PCFSoftShadowMap` による見た目の近似。実際の半影（ペナンブラ）の大きさとは対応していない |

## 5. `config/site.json` の追加項目

| 項目 | 内容 |
|---|---|
| `window.widthM` / `heightM` | 窓の実寸（m） |
| `window.sillHeightM` | 床から窓の下端までの高さ（m） |
| `room.widthM` / `depthM` / `heightM` | 部屋の寸法（m）。実際の部屋の寸法ではなく、光の見え方を確認するための仮のボックス |

いずれも現地未計測の仮値。検証場所・本番の実測値が分かり次第、更新すること（`window.widthM` は `room.widthM` より、`window.sillHeightM + heightM` は `room.heightM` 以下である必要があり、外れると起動時にエラーになる）。

## 6. 分かっている課題

1. **太陽光をスポットライトで近似している**：実際の平行光線に近づけるには `DirectionalLight` + シャドウカメラの範囲を窓に合わせる方式の方が正確。今は窓の影の切り取られ方を分かりやすくする優先度で `SpotLight` を選んでいる
2. **部屋の寸法・窓の実寸が仮値**：現地測定後に `config/site.json` を更新する
3. **周囲の建物による遮蔽は未考慮**（`docs/verification.md` と同じ課題）
4. **調整パネルが時刻のみ**：部屋の寸法やスポットライトの強さを画面上で調整する機能はまだない（`config/site.json` を編集して確認する）
