黒い縦線の分かったこと：

- 線は視点を回すと一緒に動いた（画面の決まった列ではなく、部屋の中や外の決まった向きの所）
- `&glassSurface=flat`（ガラスを平らに）で消えた。`&pool=0`（水盤を消す）では消えなかった。雲はもともとオフ
- 原因：Windows の GPU（WebGPU の中は Direct3D）で、うねりのあるガラスの所の計算が、まれに壊れた値（NaN）になる。Mac（Metal）では起きない
- 直し方：1 画素の中の 4 点のうち、壊れた値の点を捨てて、残りの点の平均で埋めるようにした（WebGPU 版・WebGL2 版の両方）。どの式で壊れた値になるかまでは突き止めていない

## room モードを初めて開くと止まる件（Electron アプリ・Windows）

（2026-10-27）

### 起きたこと

Electron アプリ（`npm run app:forever`）で room モードに切り替えると、画が黒いままで、次のログが毎回同じ流れで出た。

1. `mode-switch` で room に切り替え、`renderer-ready` はすぐ出る
2. 約 17 秒後に `unresponsive`（描画プロセスが応答しない）
3. 10 秒後に `recover`（`crash-and-reload`）で描画プロセスを強制終了
4. GPU プロセスが落ちる（`exitCode 2`）。復帰しなければ `recreate-window` でウィンドウを作り直す

同じ PC の Chrome では固まらず、60fps で動いた。

### 切り分けたこと

| 確かめたこと | 結果 |
|---|---|
| PC の GPU | HP OMEN 35L。**GeForce RTX 5070 Ti**（Intel 内蔵 GPU もあるが使われていない）。性能不足ではない |
| Electron の GPU の選び方 | WebGL も WebGPU も RTX 5070 Ti（NVIDIA Blackwell）を使う。省電力・高性能のどの指定でも同じ |
| Electron は WebGL2 に切り替わっていたか | **いいえ**。パネルは `描画 WebGPU`、`FPS 60.0`。ただし `initWebGpu()`（`src/gpu/webgpu.ts`）は失敗すると**何も出さずに WebGL2 に切り替える**ので、ログだけでは分からない。確かめるにはパネルの「描画」の行を見る |
| Chrome と Electron の違い | Chromium が Chrome 156 と Electron 152。Chrome で開いたのは開発サーバー（圧縮なし）、Electron はビルド済み（圧縮版） |
| Electron で room モードを開いた時間 | 1 回目：読み込みから**約 40 秒**、描画プロセスが応答しなかった。2 回目：1 秒後には応答し、そのまま 60fps |

### 原因

room モードの巨大なシェーダーを、Windows の GPU 向け（WebGPU の中は Direct3D 12）に**初めて組み立てる処理が、約 40 秒かかって描画が止まる**。組み立てた結果は保存され、2 回目からは一瞬で済む。Mac（Metal）では速く済むので、Mac では目立たない。

アプリの見張りは、「応答なし」から 10 秒で描画プロセスを強制終了し、読み込み直していた。強制終了すると組み立てがやり直しになり、保存もされないので、**いつまでも終わらなかった**（黒い画、GPU プロセスの終了、ウィンドウの作り直しはその結果）。

### 直したこと

`config/app.json` に `startupGraceSec`（既定 180 秒）を足した。読み込みの直後、この秒数のあいだは、「応答なし」でも復帰処理に入らず待つ。

- 猶予が終わっても止まったままなら、これまでどおり復帰する（「応答なし」の 10 秒後。描画プロセスを落とす → それでも戻らなければウィンドウを作り直す）
- ふだんの見張り（動いている最中に固まったとき）は変えていない。猶予は、読み込み・再読み込み・復帰・毎日 4:00 の再読み込み・モード切り替えの直後にだけ効く
- 復帰のたびに猶予がやり直しになるので、**本当に固まったときの復帰は、これまでより遅くなる**（最大で猶予 180 秒＋`heartbeatTimeoutSec` 30 秒）。展示の PC では許せる範囲だが、気になるなら `startupGraceSec` を下げる（実測の初回の組み立て 約 40 秒より十分長く。短すぎると同じ問題に戻る）
- `first-heartbeat`（`afterLoadSec`）をログに出すようにした。読み込みから最初の描画の知らせまでの秒数で、初回の組み立ての長さの目安になる（描画側の知らせは 10 秒ごとなので、組み立ての時間より約 10 秒長く出る）

### 確かめたこと

- 空のデータの保存先（`--user-data-dir`）で、room モードを保存なしの状態から起動し、約 2 分半動かした：`first-heartbeat` は読み込みから 23 秒後。`recover`・`render-process-gone`（アプリ側の強制終了）は出なかった
- ただしこの回は、GPU ドライバ側の保存が一部残っていたためか、組み立てが 23 秒と、最初に測った約 40 秒より短かった。**「応答なし」が出て猶予で待つ流れ（`unresponsive` に `graceLeftSec` が付く）は、まだ実際には通っていない**。別の PC・ドライバを入れ直した直後などで、確かめられたら追記する
- テスト（`tests/config.test.ts`）：`startupGraceSec` を省くと 180、短すぎる値は誤り

### 展示の PC（Mac mini）では

Mac（Metal）では組み立てが速いので、見張りを緩めた影響はほとんどない。Windows の PC を使う場合は、**初回の起動で組み立てが終わるまで、画が黒いまま数十秒かかる**ことがある。展示の前に、本番の設定で 1 回起動して待っておくと、次からは一瞬で立ち上がる。

### 使った確認の方法（再現したいときに）

- Electron がどの GPU を使うか：Electron の `app.getGPUInfo('complete')`（`GL_RENDERER`）と、`navigator.gpu.requestAdapter()` の `info`
- 描画が WebGPU か WebGL2 か：パネルのいちばん下の `描画 …`
- 初回の長さ：`logs/` の `first-heartbeat`

## 準備

1. 最新版を取る：`git pull`（`main` の 64cbca9 以降）
2. はじめてなら `npm install`
3. `npm run dev` で開発サーバーを起こし、Chrome で `http://localhost:5173/?mode=room` を開く
4. 部屋の設定（`config/room.json`）は git に入っていないので、その PC で保存してある設定がそのまま使われる。ガラスの表面を必ず「うねり」にして確かめたいときは、URL に `&glassSurface=swell` を付ける

パネルのいちばん下の文字に、確認に使う値が出る：

- `描画 WebGPU  倍率 1` … 描き方（WebGPU か WebGL2）と、画面の拡大率
- `計算 873×575` … 実際に計算している画の大きさ
- `FPS 60.0（1 フレーム 16.7 ms）` … 重さ

## 確認 1：黒い縦線が出ないこと（お願いしたいのはこれ）

一度は消えたことを確かめたが、時間や見え方を変えても出ないかを見る。

| # | やること | 見ること |
|---|---|---|
| 1-1 | いつもの設定で、10 分以上流す | 黒い点・線がちらつかないか |
| 1-2 | マウスで視点を左右・上下に回す。ホイールで寄る・引く | どの向きでも出ないか |
| 1-3 | URL に `&glassSurface=swell` を付ける（全部のガラスをうねりに） | 出ないか |
| 1-4 | URL に `&glassSurface=wave` を付ける（波打ち） | 出ないか |
| 1-5 | URL に `&glassSurface=reeded` を付ける（リブ） | 出ないか |
| 1-6 | 画面の「時刻」の欄のスライダーで、昼・夕方・夜に変える（URL なら `&t=2026-11-24T12:00` のように付ける） | どの時間でも出ないか |

## 確認 2：WebGL2 版が固まる件（必要なときだけ）

ふだんは WebGPU で描くので、WebGPU が使えない PC で流す予定がなければ、やらなくてよい。

| # | やること | 見ること |
|---|---|---|
| 2-1 | URL に `&gpu=webgl` を付けて開き、2〜3 分待つ | 画が出てくるか、黒いまま固まるか |
| 2-2 | 固まったら F12 で開発者ツールを開き、Console の赤い文字（エラー）を写す | `CONTEXT_LOST`・`shader`・`timeout` などの言葉があるか |
| 2-3 | アドレス欄に `chrome://gpu` と入れて開き、「Graphics Feature Status」と「GL_RENDERER」の行を写す | GPU の名前と、WebGL の描き方（ANGLE の Direct3D11 など） |

見込み：Windows の WebGL は描画の計算を Direct3D 用に訳し直すので、この部屋の大きな計算では、その訳し直しに時間がかかりすぎて止まった可能性が高い（まだ確かめていない）。

## 確認 3：重さ（ついでに）

確認 1 のいつもの設定で、パネルの `FPS` と `1 フレーム … ms` を写してほしい。GPU の名前（`chrome://gpu` の GL_RENDERER の行）も一緒に。Mac（Apple M4）では、四角い部屋で 1 フレーム約 6〜9ms。
